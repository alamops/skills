# Repo probes: where things live, per framework

The Project Profile and every lane depend on finding the same dozen artifacts. Where they live depends on the framework, and in managed setups (Expo without a committed `ios/`, Flutter add-to-app, Unity) some only exist after a build step — report those as "generated at build time; inspected `<config>` instead" rather than as absent.

**Contents:** [Artifact locations](#artifact-locations) · [SDK signals](#sdk-signals-for-the-project-profile) · [Pitfalls](#pitfalls)

## Artifact locations

| Artifact | Native (Xcode) | React Native (bare) | Expo (managed) | Flutter | Capacitor / Ionic |
| --- | --- | --- | --- | --- | --- |
| Info.plist keys | `<Target>/Info.plist`, plus `INFOPLIST_KEY_*` build settings in `project.pbxproj` / `.xcconfig` | `ios/<App>/Info.plist` | `app.json` / `app.config.*` → `expo.ios.infoPlist`, plus keys generated by config plugins (`expo.plugins` options such as `cameraPermission`) and first-class fields (`ios.requireFullScreen` → `UIRequiresFullScreen`, `orientation`, `ios.supportsTablet`) | `ios/Runner/Info.plist` | `ios/App/App/Info.plist` |
| Entitlements | `*.entitlements`, `CODE_SIGN_ENTITLEMENTS` | `ios/<App>/*.entitlements` | `expo.ios.entitlements`, `usesAppleSignIn`, plugin-added | `ios/Runner/*.entitlements` | `ios/App/App/*.entitlements` |
| Privacy manifest | `PrivacyInfo.xcprivacy` in the app target + each SDK bundle | `ios/<App>/PrivacyInfo.xcprivacy`, `node_modules/**/PrivacyInfo.xcprivacy` | `expo.ios.privacyManifests` (merged with module manifests at prebuild) | `ios/Runner/PrivacyInfo.xcprivacy`, plugin pods | `ios/App/App/PrivacyInfo.xcprivacy` |
| Deployment target | `IPHONEOS_DEPLOYMENT_TARGET` | `ios/Podfile` `platform :ios`, pbxproj | `expo-build-properties` → `ios.deploymentTarget` (else the SDK default) | `ios/Podfile`, `ios/Flutter/AppFrameworkInfo.plist` `MinimumOSVersion` | `ios/App/Podfile`, pbxproj |
| Toolchain (Xcode/SDK) | CI config, `.xcode-version`, fastlane, Xcode Cloud | same | `eas.json` → `build.<profile>.ios.image` (the image name encodes the Xcode version) | CI, `.fvmrc`/Flutter version → Xcode requirement | CI |
| App life cycle | `@main App` (SwiftUI, scene-based) vs `AppDelegate` + `SceneDelegate` + `UIApplicationSceneManifest` | `ios/<App>/AppDelegate.*`, `SceneDelegate.*` | framework template — decided by the Expo SDK version | `ios/Runner/AppDelegate.swift`, `SceneDelegate.swift` | `ios/App/App/AppDelegate.swift` (Capacitor 8.5+ scene-based) |
| Store metadata / screenshots | `fastlane/metadata/`, `fastlane/screenshots/`, `fastlane/Snapfile` | same | `store.config.json` (EAS Metadata), fastlane if present | same | same |

## SDK signals for the Project Profile

Look in `Podfile.lock`, `Package.resolved`, `package.json`, `pubspec.yaml`, `build.gradle` (ignore — Android), Unity `Packages/manifest.json`. The presence of a package isn't use — confirm an import or init call before a lane treats it as live.

| --- | --- | --- |
| Attribution / ads / tracking | AppsFlyer (`react-native-appsflyer`, `appsflyer_sdk`), Adjust, Branch, Singular, Kochava, Meta/Facebook SDK (`FBSDKCoreKit`, `react-native-fbsdk-next`), Google Mobile Ads / AdMob, AppLovin, ironSource, Unity Ads, TikTok Business SDK, `ASIdentifierManager`/`advertisingIdentifier` | ATT, App Privacy, 2.5.18 ads, 5.1.2 |

## Pitfalls

- **Expo managed projects have no Info.plist in the repo.** The keys come from `app.json`/`app.config.*` and plugins; cite those lines as evidence (`app.json:14 "requireFullScreen": true`).
- **Config can be dynamic.** `app.config.ts` and xcconfigs may branch on environment — check the production profile (`eas.json` `production`, the Release configuration), not the debug one.
- **Monorepos:** the iOS app may be in `apps/mobile/`, `packages/app/`, or `ios/` at the root. Profile each shipping target separately (main app, extensions, App Clip, watch app) — extensions carry their own deployment target and privacy manifest.
- **Lockfiles beat manifests** for "which version actually ships" (`Podfile.lock`, `package-lock.json`/`yarn.lock`/`pnpm-lock.yaml`, `pubspec.lock`).
